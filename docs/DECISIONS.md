### D-01〜D-19（2026-11-08 確定）

| ID | 論点 | 確定内容 |
|---|---|---|
| D-01 | 難易度の上げ方 | B→C（出現頻度を上げ、間隔が下限に達したら間隔を下限に保って速度を上げる） |
| D-02 | 判定エリアの基準 | 論理座標上の長さで固定（基準速度で先行0.35秒・通常1.15秒になる長さ） |
| D-03 | 先行入力エリアの見せ方 | 見えない猶予（画面の判定枠は通常判定エリアのみ） |
| D-04 | コンボ倍率の適用タイミング | 正解でコンボを+1した後のコンボ数で倍率を決める |
| D-05 | 不正解の出土品の扱い | 押した側の箱へ×表示つきで飛ばし、コンベアから外す |
| D-06 | 同時押しの定義 | 先に押した方を有効・即判定。反対側の押下が「先の入力が押下中」かつ「40ms以内」なら無効。キーリピートは常に無視。タッチも同じ |
| D-07 | 出現パターンの中身 | 確率の偏りで実装（連続：同じ75%／交互：違う80%／偏り：75:25）。8個ごとに抽選。どの1個も各分類20%未満にしない。連続回数の上限は設けない |
| D-08 | リザルト項目と定義 | 最終スコア・正解数・仕分け数・ミス数（内訳）・最大コンボ・正答率（正解÷(正解+誤仕分け+見逃し)）・プレイ時間（一時停止を除く）・ベストスコア |
| D-09 | 一時停止・メニュー | 一時停止画面＝メニュー（再開・リトライ・タイトル・操作説明）。PCはSpaceで一時停止/再開、Escでも一時停止メニュー。スマホは上部ボタン。停止中は出土品を隠す。再開は即時。非表示・フォーカス喪失・画面の向きの変更で自動一時停止 |
| D-10 | ゲームオーバーの流れ | 3回目のミスで即停止→約1秒の演出→リザルト。表示後0.8秒はリトライ不可。リトライはボタン・Enter・R（Spaceは無効） |
| D-11 | 技術構成 | TypeScript＋Canvas 2D（ゲーム画面）＋HTML/CSS（UI）＋Vite＋Vitest |
| D-12 | 画面レイアウト | スマホ縦：下部を左右2分割したボタン＝回収箱／スマホ横：左右端に縦長ボタン／PC：中央コンベア・左右回収箱・キー表示。ボタン表示はタッチ可能機器のみ、キーボードは常時受付 |
| D-13 | タッチ入力方式 | pointerdownで即判定。指を滑らせての入力なし。スクロール・拡大・長押しメニュー等を抑止。イベント発生時刻で判定 |
| D-14 | グラフィック | 自作ベクター描画＋作り置き。形は考古学的に正しく、色・大きさは両分類共通の範囲でランダム。種類は要件定義書D-14の表（各8種） |
| D-15 | 音 | ブラウザ内で合成した効果音。BGMは後日。音量・ミュートあり |
