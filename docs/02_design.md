## 1. 全体構成

```
ブラウザ
├─ DOM（HTML/CSS）……… HUD、仕分けボタン、タイトル・遊び方・一時停止・リザルト画面

    ├─ core/   ゲームロジック（DOM・Canvasに一切依存しない。テスト対象）
```

データの流れ（1フレーム）：

```

requestAnimationFrame ─→ 時計（一時停止を除いたゲーム時刻）─→ core.advanceTo(時刻)

core の状態（出土品の位置など）─→ Canvas描画
```

## 2. 座標と時間

### 2.1 論理座標（PC・スマホ共通。P-17の公平性）

ゲームロジックは画面のピクセルを使わず、次の論理座標で動く。描画時だけ画面に合わせて拡大縮小する。

| 名前 | 値 | 意味 |
|---|---|---|
| y軸 | 下向きが正 | コンベアの進行方向 |
| `VIEW_TOP` | 0 | 画面に見えるコンベアの上端 |
| `JUDGE_Y` | 1000 | 判定ライン |
| `VIEW_BOTTOM` | 1060 | 画面に見えるコンベアの下端（見逃した出土品が少し見える） |
| `ITEM_SIZE` | 170 | 出土品の枠の大きさ（縦横） |
| `SPAWN_Y` | −85 | 出現位置（出土品の中心。画面のすぐ上の見えない所） |
| `BELT_WIDTH` | 260 | コンベアの幅 |
| `MIN_SPACING` | 200 | 出土品の中心どうしの最小間隔（大きさ170＋すき間30） |

出土品の位置は**中心**で表す。

### 2.2 基準速度と判定エリア（D-02・D-03）

| 名前 | 値 | 計算 |
|---|---|---|
| `BASE_TRAVEL_SEC` | 3.5秒 | 基準速度で y=0 から判定ラインまでかかる時間 |
| 基準速度 `BASE_SPEED` | 285.7／秒 | 1000 ÷ 3.5 |
| 先行入力エリアの長さ | 100 | 0.35秒 × 基準速度 |
| 通常判定エリアの長さ | 328.6 | 1.15秒 × 基準速度 |
| `EARLY_START` | 571.4 | 1000 − 100 − 328.6 |
| `NORMAL_START` | 671.4 | 1000 − 328.6 |

出土品の中心 y によるエリア（境界は「上側の値を含み、下側を含まない」）：

| エリア | 範囲 | 入力 |
|---|---|---|
| 待機 | y < 571.4 | 無視 |
| 先行入力 | 571.4 ≦ y < 671.4 | 即判定 |
| 通常判定 | 671.4 ≦ y < 1000 | 即判定 |
| 判定ライン通過 | y ≧ 1000 | その瞬間に見逃しミス |

画面に描く判定枠は通常判定エリア（671.4〜1000）だけ。
先行入力の開始位置（571.4）は、出土品の下端（中心＋85）が判定枠の上端に触れる位置（586.4）とほぼ同じになる。
つまり「出土品が枠に触れたら押せる」と見た目どおりに感じられる。

### 2.3 コンベアの動き（C-14・C-15）

- コンベア上の出土品はすべて同じ速度で一緒に動く。コンベアの累計移動距離を `D` とし、出土品は出現時の `D` を覚えておく。
  - 出土品の位置 ＝ `SPAWN_Y + (D − 出現時のD)`
  - したがって出土品どうしの間隔は出現後に変わらない。仕分けても他の出土品は止まらず、瞬間移動もしない。
- 速度が変わるのは出土品が出現した瞬間だけ（第4章）。速度が一定の区間では位置は時刻の一次式で、正確に計算できる。

### 2.4 ゲーム時刻（C-40・C-44）

- ゲーム時刻 ＝ プレイ開始からの経過時間から、一時停止していた時間を除いたもの。プレイ時間（D-08）はこれを使う。
- 毎フレーム、実時間の経過をゲーム時刻に加える。ただし1フレームで進める量は最大0.1秒に制限する。
  端末が一瞬固まったときに、まとめて進んで理不尽な見逃しミスが出ることを防ぐ。
- 入力の時刻はイベントの発生時刻（`event.timeStamp`）をゲーム時刻に換算して使う（D-13）。
  ただし、すでに計算済みの時刻より前にはできないため、その場合は計算済みの時刻に合わせる。

### 2.5 ロジックの進め方（フレームレートに依存しない）

`advanceTo(t)` は、次に起きる出来事（出土品の出現、先頭の判定ライン通過）の時刻を計算し、時刻順に処理しながら t まで進める。

```
ループ:
  次の出現時刻 = 現在時刻 + (次の出現位置のD − D) ÷ 速度
  次の通過時刻 = 現在時刻 + (JUDGE_Y − 先頭の y) ÷ 速度   （出土品がなければ ∞）
  早い方が t より後なら → D と時刻を t まで進めて終了
  早い方まで進める
  通過が先（同時なら通過を先）→ 見逃しミス処理（ゲームオーバーなら停止）
  出現が先 → 出現処理
```

固定刻みの近似ではなく出来事の時刻で正確に計算するので、30fpsでも144fpsでも結果は同じになる。
同じ乱数の種と同じ入力なら、何度実行しても同じ結果になる（テストと不具合の再現に使う）。

## 3. ゲーム本体（core/game.ts）

### 3.1 状態

| 名前 | 内容 |
|---|---|
| `time` | ゲーム時刻（秒） |
| `D` / `speed` | コンベアの累計移動距離／現在の速度 |
| `items` | コンベア上の出土品（出現順。先頭＝`items[0]`） |
| `spawnedCount` / `nextSpawnD` | 出現済みの数／次の出現位置 |
| `score` / `combo` / `maxCombo` | 得点／コンボ／最大コンボ |
| `correct` / `wrong` / `passed` | 正解数／誤仕分け数／見逃し数 |
| `misses` | ミス数（＝誤仕分け＋見逃し） |
| `status` | `playing` か `over` |
| `overTime` | ゲームオーバーになった時刻 |

出土品：`id`、`category`（haniwa / dogu）、`variantId`（種類）、`look`（色・大きさ・傾き・左右反転）、`spawnD`。

### 3.2 押したとき：`press(side, t)`

1. `advanceTo(t)` で t まで進める。
2. `status` が `over` なら無視。
3. 先頭の出土品がなければ無視。
4. 先頭のエリアが「待機」なら無視（罰なし。C-18）。
5. 先行入力・通常判定エリアなら、その場で正誤判定：
   - 正解（左＝はにわ、右＝土偶）
     1. `combo += 1`、`maxCombo` を更新
     2. 倍率 ＝ 倍率表(`combo`)（**加算後のコンボ数**。D-04）
     3. 得点 ＝ 100 × 倍率（表の値ではすべて整数になる）
     4. `score += 得点`、`correct += 1`
     5. 出土品をコンベアから外し、「正解」イベントを出す（行き先は押した側＝正しい箱）
     6. コンボが節目（10・20・40・70・100、以後50ごと。D-18）なら「節目」イベントを出す
   - 不正解
     1. `misses += 1`、`wrong += 1`、`combo = 0`
     2. 出土品をコンベアから外し、「誤仕分け」イベントを出す（行き先は押した側の箱。D-05）
     3. `misses` が3なら「ゲームオーバー」
6. 次の出土品が先頭になる。演出中でも次の入力をすぐ受け付ける（C-09。演出は描画側だけで行うため）。

### 3.3 見逃し

先頭の中心が `JUDGE_Y` に達した瞬間：`misses += 1`、`passed += 1`、`combo = 0`、出土品を外して「見逃し」イベント。3回目ならゲームオーバー。

### 3.4 ゲームオーバー（D-10）

3回目のミスの瞬間に `status = over`、`overTime = time`。以後 `advanceTo` も `press` も何もしない（コンベアが止まる）。
画面側は約1秒の終了演出のあとリザルトを出す。

### 3.5 イベント

core はイベントを列にためるだけで、演出や音のことは知らない。

| イベント | 中身 |
|---|---|
| `spawn` | 出土品 |
| `correct` | 出土品、外した時の y、左右、得点、倍率、コンボ |
| `wrong` | 出土品、外した時の y、押した左右 |
| `passed` | 出土品 |
| `milestone` | コンボ数、倍率 |
| `gameover` | 時刻 |

### 3.6 リザルトの集計（D-08）

| 項目 | 計算 |
|---|---|
| 最終スコア | `score` |
| 正解数 | `correct` |
| 仕分け数 | `correct + wrong` |
| ミス数 | `misses`（内訳：誤仕分け `wrong`、見逃し `passed`） |
| 最大コンボ | `maxCombo` |
| 正答率 | `correct ÷ (correct + wrong + passed)` を％・小数1桁。分母0なら「—」 |
| プレイ時間 | `overTime`（分:秒） |
| ベストスコア | 保存値と比べ、更新したら「NEW」表示 |

## 4. 難易度（D-01・D-17）

出現する出土品の番号 n（0から数える＝その時点までの累計出現数）で、次の2つを決める。値は下の制御点を直線でつなぐ（なめらかに変化。D-17）。最後の制御点より先は最後の値のまま。

- **出現間隔（基準速度での秒数）**：B段階で縮める。
- **速度倍率**：C段階で上げる。

| n | 出現間隔（秒、基準速度） | 速度倍率 | 段階 |
|---|---|---|---|
| 0 | 1.80 | 1.0 | B |
| 20 | 1.40 | 1.0 | B |
| 50 | 1.10 | 1.0 | B |
| 100 | 0.85 | 1.0 | B |
| 150 | 0.70（＝下限） | 1.0 | B→C |
| 250 | 0.70 | 1.3 | C |
| 400 | 0.70 | 1.7 | C |
| 600 | 0.70 | 2.2 | C |
| 900〜 | 0.70 | 3.0（上限） | C |

出現処理（出土品 n）：
1. 速度 ＝ 基準速度 × 速度倍率(n)
2. 次の出現位置 ＝ 現在のD ＋ max(`MIN_SPACING`, 出現間隔(n) × 基準速度)
   → 間隔が `MIN_SPACING`（200）より狭くなることはない（C-15・C-34）

この初期値で計算した目安（ミスせず進んだ場合）：

| n | 到達時刻 | 毎秒の個数 | 判定可能時間 | 判定エリア内に同時にある数 |
|---|---|---|---|---|
| 0 | 0:00 | 0.56 | 1.50秒 | 約1 |
| 150 | 約2:37 | 1.43 | 1.50秒 | 約2 |
| 250 | 約3:38 | 1.86 | 1.15秒 | 約2 |
| 400 | 約4:48 | 2.43 | 0.88秒 | 約2 |
| 600 | 約6:00 | 3.14 | 0.68秒 | 約2 |
| 900〜 | 約7:21〜 | 4.29 | 0.50秒 | 約2 |

- 序盤は暫定表（2.0秒）より少し速い1.8秒から始める（P-09）。最初の出土品が押せるようになるのは開始から約2.3秒後で、これが開始前の待ち時間を兼ねる。
- 速度3.0倍・毎秒4.3個は人の限界を超えると推測され、エンドレスでも必ず終わる。
- 目標（初心者1〜2分／慣れた人3〜5分）に合うかは第4段階の試遊で確かめて調整する。

## 5. 出土品の生成（spawner.ts）

### 5.1 分類の抽選（D-07）

| パターン | 選ばれる重み | 次の1個が「はにわ」になる確率 |
|---|---|---|
| 完全ランダム | 50 | 0.5 |
| 同分類の連続 | 20 | 前がはにわなら0.75、土偶なら0.25 |
| 交互出現 | 15 | 前がはにわなら0.2、土偶なら0.8 |
| 片方に偏る | 15 | 偏る側（パターン開始時に50%で決定）がはにわなら0.75、土偶なら0.25 |

- 8個ごとにパターンを抽選し直す。パターンが変わっても「前の分類」は引き継ぐ。
- ゲーム最初の1個は「前」がないので0.5。
- 確率は必ず0.2〜0.8の範囲に収める（どの1個も、はにわ・土偶の両方になりうる。C-30）。
- 「◯回続いたら切り替える」処理は入れない。

### 5.2 見た目の抽選（C-32・D-14）

- 種類：その分類の種類から均等に選ぶ。ただし直前と同じ種類は避ける（分類の予測には使えない。見た目の単調さを減らすため）。
- 色：共通の土色パレット6色から均等に選ぶ（はにわ・土偶で同じパレット・同じ確率）。
- 大きさ：0.92〜1.04倍の一様乱数（両分類共通）。
- 傾き：−5°〜＋5°の一様乱数（両分類共通）。
- 左右反転：50%（両分類共通）。
- 各種類の絵は `ITEM_SIZE` の枠に収まるように描く。実物の大きさの差（埴輪は大きく土偶は小さい）は表示に反映しない。

## 6. 入力

### 6.1 共通の仲裁（core/inputArbiter.ts、D-06）

入力元ごとにID（例：`key:KeyA`、`pointer:3`）を付けて、押下と離しを受け取る。

```
押下(入力元, 左右, 時刻):
  その入力元がすでに押下中 → 無視（長押し・リピート）
  押下中として記録
  反対側に押下中の入力元がある かつ 時刻 − 反対側が最後に受け付けた時刻 ≦ 0.040秒 → 無視（同時押し）
  それ以外 → 受け付け（この側の最後に受け付けた時刻を更新）→ core.press(左右, 時刻)
離し(入力元): 押下中の記録を消す
全解除: 画面が非表示・フォーカス喪失のとき、押下中の記録をすべて消す
```

- 左右どちらかの2つのキー（Aと←など）は別の入力元として扱う。Aを押しながら←を押すと2回の押下になる（それぞれ1個ずつ処理）。
- 同時押しで無視された入力には何の反応も出さない。

### 6.2 キーボード（input/keyboard.ts）

| キー（`event.code`） | プレイ中 | 一時停止中 | リザルト |
|---|---|---|---|
| KeyA / ArrowLeft | はにわ（左） | — | — |
| KeyD / ArrowRight | 土偶（右） | — | — |
| Space | 一時停止 | 再開 | 無効（D-10） |
| Escape | 一時停止メニュー | 再開 | — |
| Enter / KeyR | — | — | リトライ（表示後0.8秒は無効） |

- `event.repeat` が真の押下は無視する。
- Space・矢印キーは `preventDefault` でページのスクロールを止める。
- 物理キーの位置（`event.code`）で判定するので、日本語入力の状態やキー配列の違いの影響を受けない（日本語入力がオンのときにも動くかは実機で確認する）。

### 6.3 タッチ（input/touch.ts、D-13）

- 仕分けボタンの `pointerdown` で即判定（`pointerType` を問わない）。`pointerup`・`pointercancel` で離し。クリックイベントは使わない。
- 指を滑らせて反対側のボタンに入っても入力しない（`pointerdown` だけを入力とするため）。
- 誤操作の抑止：
  - viewport：`width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover`
  - ゲーム画面全体：`touch-action: none`、`user-select: none`、`-webkit-touch-callout: none`、`-webkit-tap-highlight-color: transparent`、`overscroll-behavior: none`
  - `html, body` を `position: fixed`、高さ `100dvh` にしてページ自体をスクロールさせない
  - `touchstart` と `gesturestart`（iPhoneのSafari）の既定動作を止める（`passive: false`）、`contextmenu` を止める
- 仕分けボタンはタッチ操作ができる機器だけに表示する：`matchMedia('(pointer: coarse)')`、または最初のタッチを検出したとき。キーボードは常に受け付ける（P-20）。

### 6.4 自動一時停止（D-09）

`visibilitychange`（非表示）、`blur`、`pagehide`、画面の向き（縦⇔横）の変化で、プレイ中なら一時停止し、入力の押下記録を全解除する。
PCでウィンドウの大きさを変えただけなら一時停止せず、配置だけ直す。

## 7. 画面（app/layout.ts、ui/）

Canvasは画面全体に1枚敷き、その上にDOMのHUD・ボタン・画面を重ねる。仕分けた出土品はCanvas上でボタン（回収箱）の位置まで飛ぶ。

### 7.1 配置の切り替え（D-12・D-19）

| 配置 | 条件 |
|---|---|
| スマホ縦 | タッチ可能 かつ 高さ ≧ 幅 |
| スマホ横 | タッチ可能 かつ 幅 ＞ 高さ |
| PC | タッチ不可（向きに関係なく） |

### 7.2 スマホ縦（基本）

```
┌──────────────────────┐ ← セーフエリア（切り欠き）を避ける
│ 12,340  ×1.5 23COMBO  ● ● ○  ⏸ │ HUD（高さ約56px）
├──────────────────────┤
│        │░░░░░░│        │
```

## 8. 描画と演出（render/）

### 8.1 描画

- Canvasの解像度倍率（devicePixelRatio）は最大2。
- 出土品の絵は「種類×色」ごとに、現在の表示サイズで一度だけ画像に描いて保存し、毎フレームは貼り付けるだけにする。画面サイズが変わったら作り直す。
- コンベアの表面の模様を `D` に合わせて流し、動いていることが見えるようにする。
- 一時停止中は出土品を描かない。

### 8.2 演出（C-39。どれもコンベアと出土品を隠さない）

| 場面 | 演出 | 長さ |
|---|---|---|
| 正解 | 出土品が押した側の箱（ボタン）へ弧を描いて飛び込む。箱の近くに「+120」。コンボ表示が少し弾む | 約0.25秒（飛行）、0.5秒（得点） |
| 誤仕分け | 出土品が押した側の箱へ飛び、赤い✕印。箱が赤く光る。ミスの印が1つ埋まって揺れる | 約0.3秒 |
| 見逃し | 出土品が判定ラインを越えて落ち、薄れて消える。「見逃し」の文字。ミスの印が埋まる | 約0.4秒 |
| コンボの節目 | HUDのコンボ表示が大きく光り「20 COMBO! ×1.5」。画面の縁が一瞬光る | 約0.8秒 |
| ゲームオーバー | コンベアが止まり、画面が暗くなって「終了」 | 約1秒 → リザルト |

- 正誤は色だけでなく形（○・✕）でも示す（色の見分けにくい人への配慮）。
- 飛んでいる出土品はロジックからは外れているので、次の出土品の入力をじゃましない。

### 8.3 描画負荷の調整（C-43）

- 直近3秒の平均フレーム時間が20ミリ秒を超えたら、低画質に切り替える：解像度倍率の上限を1.5に下げ、演出の粒の数を減らす（最大64個→24個）。
- プレイ中に高画質へは戻さない（ちらつき防止）。次のプレイ開始時に高画質から測り直す。
- 演出用のオブジェクトは使い回し（オブジェクトプール）、長時間プレイでもメモリが増えないようにする。

## 10. 音・保存・デバッグ

### 10.1 効果音（audio/sfx.ts、D-15）

Web Audio APIで合成する（音声ファイルなし）。

| 場面 | 音 |
|---|---|
| 正解 | 短く明るい音。倍率が上がるほど少し高い音 |

| 見逃し | 鈍い音 |
| コンボの節目 | 短い上昇音（アルペジオ） |
| ゲームオーバー | 下降音 |

音のオン/オフはタイトルと一時停止画面で切り替え、保存する。

### 10.2 保存（app/storage.ts、D-16）

localStorage のキー `haniwa-dogu-sort/v1` に `{ bestScore, muted }` を保存。読み書きは失敗しても動くようにする（プライベートブラウズなど）。

### 10.3 開発用（I-06〜I-08、仕様に影響しない手法として採用）

- URLに `?debug=1`：各エリアの境界線、現在の n・速度・出現間隔・パターン、フレーム時間を表示。
- URLに `?seed=123`：乱数の種を固定。
- 一般のプレイヤーには表示しない。

## 12. この設計で決めた細部（遊び心地に関わるもの。承認対象）

| # | 内容 | 理由 |
|---|---|---|
| 1 | 出土品の位置は中心で判定。先行入力の開始は「出土品が判定枠に触れたあたり」 | 見た目と判定を一致させる |
| 2 | 難易度の初期値は第4章の表（序盤1.8秒間隔、150個目で下限0.7秒、以後は速度を最大3.0倍まで） | D-01・D-17の目標に合わせた試算。調整段階で変更 |
| 3 | 開始のカウントダウンはなし（最初の出土品が押せるまで約2.3秒かかり、これが準備時間になる） | テンポ優先 |
| 4 | 同じ側の別キー（Aと←）は別の押下として数える | 「1回の押下で1個」に素直に従う |
| 5 | 1フレームで進めるゲーム時間は最大0.1秒 | 端末が固まったときの理不尽なミスを防ぐ |
| 6 | 同じ種類が2回続けて出ないようにする | 見た目の単調さを減らす（分類の予測には使えない） |
| 7 | PCでウィンドウの大きさを変えても一時停止しない（スマホで向きが変わったときだけ一時停止） | PCでは不要な中断を避ける |
| 8 | 「遊び方」画面に、全16種の絵と名前を一覧で載せる | 初めての人が見分け方を学べる。プレイ中には名前を出さない（I-02は未採用のため） |

## 13. テスト方針

### 13.1 自動テスト（Vitest、core のみ）

| 対象 | 確かめること |
|---|---|
| 得点 | 倍率の境界（9/10、19/20、39/40、69/70、99/100）、加算後のコンボで倍率が決まること |
| エリア | 各境界の値で正しいエリアになること |
| 本体 | 待機中の入力は無視・罰なし／先行・通常エリアで即判定／誤仕分けで出土品が外れコンボ0／判定ライン到達で見逃しミス／3ミスで終了し以後の入力は無視／仕分けても他の出土品の位置が変わらないこと |
| 難易度 | n＝0〜5000で間隔が `MIN_SPACING` 未満にならない／速度・間隔の曲線が表どおり |
| 出現 | 10万個で各分類が約50%／どの1個も確率0.2〜0.8／同じ分類が何個続いても次が確定しない／パターンの選ばれ方が重みどおり |
| 入力の仲裁 | リピート無視／反対側が押下中かつ40ms以内なら無効／40msを超えたロールオーバーは有効／離した後は有効 |
| フレーム非依存 | 同じ種・同じ入力列を、刻み1/30・1/60・1/144秒・ばらばらの刻みで進めて結果が完全一致 |

### 13.2 実機確認（第4段階）

Windows（Chrome・Edge）、iPhone（Safari）、Android（Chrome）で次を確認：入力の反応、ダブルタップ・ピンチ・スクロールが起きないこと、縦横の配置、自動一時停止、60fps、出土品の見分けやすさ、音。
macOS（Safari）はユーザーの手元に端末があれば確認する。
