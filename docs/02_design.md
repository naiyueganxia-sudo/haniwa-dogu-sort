## 2. 座標と時間

### 2.1 論理座標（PC・スマホ共通。P-17の公平性）

ゲームロジックは画面のピクセルを使わず、次の論理座標で動く。描画時だけ画面に合わせて拡大縮小する。

| 名前 | 値 | 意味 |
|---|---|---|
| y軸 | 下向きが正 | コンベアの進行方向 |
| `VIEW_TOP` | 0 | 画面に見えるコンベアの上端 |
| `JUDGE_Y` | 1000 | 判定ライン |
| `VIEW_BOTTOM` | 1060 | 画面に見えるコンベアの下端（見逃した出土品が少し見える） |
| `ITEM_SIZE` | 170 | 出土品の枠の大きさ（縦横） |
| `SPAWN_Y` | −85 | 出現位置（出土品の中心。画面のすぐ上の見えない所） |
| `BELT_WIDTH` | 260 | コンベアの幅 |
| `MIN_SPACING` | 200 | 出土品の中心どうしの最小間隔（大きさ170＋すき間30） |

出土品の位置は**中心**で表す。

### 2.2 基準速度と判定エリア（D-02・D-03）

| 名前 | 値 | 計算 |
|---|---|---|
| `BASE_TRAVEL_SEC` | 3.5秒 | 基準速度で y=0 から判定ラインまでかかる時間 |
| 基準速度 `BASE_SPEED` | 285.7／秒 | 1000 ÷ 3.5 |
| 先行入力エリアの長さ | 100 | 0.35秒 × 基準速度 |
| 通常判定エリアの長さ | 328.6 | 1.15秒 × 基準速度 |
| `EARLY_START` | 571.4 | 1000 − 100 − 328.6 |
| `NORMAL_START` | 671.4 | 1000 − 328.6 |

出土品の中心 y によるエリア（境界は「上側の値を含み、下側を含まない」）：

| エリア | 範囲 | 入力 |
|---|---|---|
| 待機 | y < 571.4 | 無視 |
| 先行入力 | 571.4 ≦ y < 671.4 | 即判定 |
| 通常判定 | 671.4 ≦ y < 1000 | 即判定 |
| 判定ライン通過 | y ≧ 1000 | その瞬間に見逃しミス |

画面に描く判定枠は通常判定エリア（671.4〜1000）だけ。
先行入力の開始位置（571.4）は、出土品の下端（中心＋85）が判定枠の上端に触れる位置（586.4）とほぼ同じになる。
つまり「出土品が枠に触れたら押せる」と見た目どおりに感じられる。

### 2.3 コンベアの動き（C-14・C-15）

- コンベア上の出土品はすべて同じ速度で一緒に動く。コンベアの累計移動距離を `D` とし、出土品は出現時の `D` を覚えておく。
  - 出土品の位置 ＝ `SPAWN_Y + (D − 出現時のD)`
  - したがって出土品どうしの間隔は出現後に変わらない。仕分けても他の出土品は止まらず、瞬間移動もしない。
- 速度が変わるのは出土品が出現した瞬間だけ（第4章）。速度が一定の区間では位置は時刻の一次式で、正確に計算できる。

### 2.4 ゲーム時刻（C-40・C-44）

- ゲーム時刻 ＝ プレイ開始からの経過時間から、一時停止していた時間を除いたもの。プレイ時間（D-08）はこれを使う。
- 毎フレーム、実時間の経過をゲーム時刻に加える。ただし1フレームで進める量は最大0.1秒に制限する。
  端末が一瞬固まったときに、まとめて進んで理不尽な見逃しミスが出ることを防ぐ。
- 入力の時刻はイベントの発生時刻（`event.timeStamp`）をゲーム時刻に換算して使う（D-13）。
  ただし、すでに計算済みの時刻より前にはできないため、その場合は計算済みの時刻に合わせる。

### 2.5 ロジックの進め方（フレームレートに依存しない）

`advanceTo(t)` は、次に起きる出来事（出土品の出現、先頭の判定ライン通過）の時刻を計算し、時刻順に処理しながら t まで進める。

```
ループ:
  次の出現時刻 = 現在時刻 + (次の出現位置のD − D) ÷ 速度
  次の通過時刻 = 現在時刻 + (JUDGE_Y − 先頭の y) ÷ 速度   （出土品がなければ ∞）
  早い方が t より後なら → D と時刻を t まで進めて終了
  早い方まで進める
  通過が先（同時なら通過を先）→ 見逃しミス処理（ゲームオーバーなら停止）
  出現が先 → 出現処理
```

固定刻みの近似ではなく出来事の時刻で正確に計算するので、30fpsでも144fpsでも結果は同じになる。
同じ乱数の種と同じ入力なら、何度実行しても同じ結果になる（テストと不具合の再現に使う）。

## 3. ゲーム本体（core/game.ts）

### 3.1 状態

| 名前 | 内容 |
|---|---|
| `time` | ゲーム時刻（秒） |
| `D` / `speed` | コンベアの累計移動距離／現在の速度 |
| `items` | コンベア上の出土品（出現順。先頭＝`items[0]`） |
| `spawnedCount` / `nextSpawnD` | 出現済みの数／次の出現位置 |
| `score` / `combo` / `maxCombo` | 得点／コンボ／最大コンボ |
| `correct` / `wrong` / `passed` | 正解数／誤仕分け数／見逃し数 |
| `misses` | ミス数（＝誤仕分け＋見逃し） |
| `status` | `playing` か `over` |
| `overTime` | ゲームオーバーになった時刻 |

出土品：`id`、`category`（haniwa / dogu）、`variantId`（種類）、`look`（色・大きさ・傾き・左右反転）、`spawnD`。

### 3.2 押したとき：`press(side, t)`

1. `advanceTo(t)` で t まで進める。
2. `status` が `over` なら無視。
3. 先頭の出土品がなければ無視。
4. 先頭のエリアが「待機」なら無視（罰なし。C-18）。
5. 先行入力・通常判定エリアなら、その場で正誤判定：
   - 正解（左＝はにわ、右＝土偶）
     1. `combo += 1`、`maxCombo` を更新
     2. 倍率 ＝ 倍率表(`combo`)（**加算後のコンボ数**。D-04）
     3. 得点 ＝ 100 × 倍率（表の値ではすべて整数になる）
     4. `score += 得点`、`correct += 1`
     5. 出土品をコンベアから外し、「正解」イベントを出す（行き先は押した側＝正しい箱）
     6. コンボが節目（10・20・40・70・100、以後50ごと。D-18）なら「節目」イベントを出す
   - 不正解
     1. `misses += 1`、`wrong += 1`、`combo = 0`
     2. 出土品をコンベアから外し、「誤仕分け」イベントを出す（行き先は押した側の箱。D-05）
     3. `misses` が3なら「ゲームオーバー」
6. 次の出土品が先頭になる。演出中でも次の入力をすぐ受け付ける（C-09。演出は描画側だけで行うため）。

### 3.3 見逃し

先頭の中心が `JUDGE_Y` に達した瞬間：`misses += 1`、`passed += 1`、`combo = 0`、出土品を外して「見逃し」イベント。3回目ならゲームオーバー。

### 3.4 ゲームオーバー（D-10）

3回目のミスの瞬間に `status = over`、`overTime = time`。以後 `advanceTo` も `press` も何もしない（コンベアが止まる）。
画面側は約1秒の終了演出のあとリザルトを出す。

### 3.5 イベント

core はイベントを列にためるだけで、演出や音のことは知らない。

| イベント | 中身 |
|---|---|
| `spawn` | 出土品 |
| `correct` | 出土品、外した時の y、左右、得点、倍率、コンボ |
| `wrong` | 出土品、外した時の y、押した左右 |
| `passed` | 出土品 |
| `milestone` | コンボ数、倍率 |
| `gameover` | 時刻 |

### 3.6 リザルトの集計（D-08）

| 項目 | 計算 |
|---|---|
| 最終スコア | `score` |
| 正解数 | `correct` |
| 仕分け数 | `correct + wrong` |
| ミス数 | `misses`（内訳：誤仕分け `wrong`、見逃し `passed`） |
| 最大コンボ | `maxCombo` |
| 正答率 | `correct ÷ (correct + wrong + passed)` を％・小数1桁。分母0なら「—」 |
| プレイ時間 | `overTime`（分:秒） |
| ベストスコア | 保存値と比べ、更新したら「NEW」表示 |

## 4. 難易度（D-01・D-17）

出現する出土品の番号 n（0から数える＝その時点までの累計出現数）で、次の2つを決める。値は下の制御点を直線でつなぐ（なめらかに変化。D-17）。最後の制御点より先は最後の値のまま。

- **出現間隔（基準速度での秒数）**：B段階で縮める。
- **速度倍率**：C段階で上げる。

| n | 出現間隔（秒、基準速度） | 速度倍率 | 段階 |
|---|---|---|---|
| 0 | 1.80 | 1.0 | B |
| 20 | 1.40 | 1.0 | B |
| 50 | 1.10 | 1.0 | B |
| 100 | 0.85 | 1.0 | B |
| 150 | 0.70（＝下限） | 1.0 | B→C |
| 250 | 0.70 | 1.3 | C |
| 400 | 0.70 | 1.7 | C |
| 600 | 0.70 | 2.2 | C |
| 900〜 | 0.70 | 3.0（上限） | C |

出現処理（出土品 n）：
1. 速度 ＝ 基準速度 × 速度倍率(n)
2. 次の出現位置 ＝ 現在のD ＋ max(`MIN_SPACING`, 出現間隔(n) × 基準速度)
   → 間隔が `MIN_SPACING`（200）より狭くなることはない（C-15・C-34）

この初期値で計算した目安（ミスせず進んだ場合）：

| n | 到達時刻 | 毎秒の個数 | 判定可能時間 | 判定エリア内に同時にある数 |
|---|---|---|---|---|
| 0 | 0:00 | 0.56 | 1.50秒 | 約1 |
| 150 | 約2:37 | 1.43 | 1.50秒 | 約2 |
| 250 | 約3:38 | 1.86 | 1.15秒 | 約2 |
| 400 | 約4:48 | 2.43 | 0.88秒 | 約2 |
| 600 | 約6:00 | 3.14 | 0.68秒 | 約2 |
| 900〜 | 約7:21〜 | 4.29 | 0.50秒 | 約2 |

- 序盤は暫定表（2.0秒）より少し速い1.8秒から始める（P-09）。最初の出土品が押せるようになるのは開始から約2.3秒後で、これが開始前の待ち時間を兼ねる。
- 速度3.0倍・毎秒4.3個は人の限界を超えると推測され、エンドレスでも必ず終わる。
- 目標（初心者1〜2分／慣れた人3〜5分）に合うかは第4段階の試遊で確かめて調整する。

## 5. 出土品の生成（spawner.ts）

### 5.1 分類の抽選（D-07）

| パターン | 選ばれる重み | 次の1個が「はにわ」になる確率 |
|---|---|---|
| 完全ランダム | 50 | 0.5 |
| 同分類の連続 | 20 | 前がはにわなら0.75、土偶なら0.25 |
| 交互出現 | 15 | 前がはにわなら0.2、土偶なら0.8 |
| 片方に偏る | 15 | 偏る側（パターン開始時に50%で決定）がはにわなら0.75、土偶なら0.25 |

- 8個ごとにパターンを抽選し直す。パターンが変わっても「前の分類」は引き継ぐ。
- ゲーム最初の1個は「前」がないので0.5。
- 確率は必ず0.2〜0.8の範囲に収める（どの1個も、はにわ・土偶の両方になりうる。C-30）。
- 「◯回続いたら切り替える」処理は入れない。

### 5.2 見た目の抽選（C-32・D-14）

- 種類：その分類の種類から均等に選ぶ。ただし直前と同じ種類は避ける（分類の予測には使えない。見た目の単調さを減らすため）。
- 色：共通の土色パレット6色から均等に選ぶ（はにわ・土偶で同じパレット・同じ確率）。
- 大きさ：0.92〜1.04倍の一様乱数（両分類共通）。
- 傾き：−5°〜＋5°の一様乱数（両分類共通）。
- 左右反転：50%（両分類共通）。
- 各種類の絵は `ITEM_SIZE` の枠に収まるように描く。実物の大きさの差（埴輪は大きく土偶は小さい）は表示に反映しない。

## 6. 入力

### 6.1 共通の仲裁（core/inputArbiter.ts、D-06）

入力元ごとにID（例：`key:KeyA`、`pointer:3`）を付けて、押下と離しを受け取る。

```
押下(入力元, 左右, 時刻):
  その入力元がすでに押下中 → 無視（長押し・リピート）
  押下中として記録
  反対側に押下中の入力元がある かつ 時刻 − 反対側が最後に受け付けた時刻 ≦ 0.040秒 → 無視（同時押し）
  それ以外 → 受け付け（この側の最後に受け付けた時刻を更新）→ core.press(左右, 時刻)
離し(入力元): 押下中の記録を消す
全解除: 画面が非表示・フォーカス喪失のとき、押下中の記録をすべて消す
```

- 左右どちらかの2つのキー（Aと←など）は別の入力元として扱う。Aを押しながら←を押すと2回の押下になる（それぞれ1個ずつ処理）。
- 同時押しで無視された入力には何の反応も出さない。

### 6.2 キーボード（input/keyboard.ts）

| キー（`event.code`） | プレイ中 | 一時停止中 | リザルト |
|---|---|---|---|
| KeyA / ArrowLeft | はにわ（左） | — | — |
| KeyD / ArrowRight | 土偶（右） | — | — |
| Space | 一時停止 | 再開 | 無効（D-10） |
| Escape | 一時停止メニュー | 再開 | — |
| Enter / KeyR | — | — | リトライ（表示後0.8秒は無効） |

- `event.repeat` が真の押下は無視する。
- Space・矢印キーは `preventDefault` でページのスクロールを止める。
- 物理キーの位置（`event.code`）で判定するので、日本語入力の状態やキー配列の違いの影響を受けない（日本語入力がオンのときにも動くかは実機で確認する）。

### 6.3 タッチ（input/touch.ts、D-13）

- 仕分けボタンの `pointerdown` で即判定（`pointerType` を問わない）。`pointerup`・`pointercancel` で離し。クリックイベントは使わない。
- 指を滑らせて反対側のボタンに入っても入力しない（`pointerdown` だけを入力とするため）。
- 誤操作の抑止：
  - viewport：`width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover`
  - ゲーム画面全体：`touch-action: none`、`user-select: none`、`-webkit-touch-callout: none`、`-webkit-tap-highlight-color: transparent`、`overscroll-behavior: none`
  - `html, body` を `position: fixed`、高さ `100dvh` にしてページ自体をスクロールさせない
  - `touchstart` と `gesturestart`（iPhoneのSafari）の既定動作を止める（`passive: false`）、`contextmenu` を止める
- 仕分けボタンはタッチ操作ができる機器だけに表示する：`matchMedia('(pointer: coarse)')`、または最初のタッチを検出したとき。キーボードは常に受け付ける（P-20）。

### 6.4 自動一時停止（D-09）

`visibilitychange`（非表示）、`blur`、`pagehide`、画面の向き（縦⇔横）の変化で、プレイ中なら一時停止し、入力の押下記録を全解除する。
PCでウィンドウの大きさを変えただけなら一時停止せず、配置だけ直す。

## 7. 画面（app/layout.ts、ui/）

Canvasは画面全体に1枚敷き、その上にDOMのHUD・ボタン・画面を重ねる。仕分けた出土品はCanvas上でボタン（回収箱）の位置まで飛ぶ。

### 7.1 配置の切り替え（D-12・D-19）

| 配置 | 条件 |
|---|---|
| スマホ縦 | タッチ可能 かつ 高さ ≧ 幅 |
| スマホ横 | タッチ可能 かつ 幅 ＞ 高さ |
| PC | タッチ不可（向きに関係なく） |

### 7.2 スマホ縦（基本）

### 8.1 描画

- Canvasの解像度倍率（devicePixelRatio）は最大2。

### 8.2 演出（C-39。どれもコンベアと出土品を隠さない）

### 8.3 描画負荷の調整（C-43）

- 直近3秒の平均フレーム時間が20ミリ秒を超えたら、低画質に切り替える：解像度倍率の上限を1.5に下げ、演出の粒の数を減らす（最大64個→24個）。

### 16.2 再計算を確実にするための変更（core）

サーバーで同じゲームを再現するには、**ブラウザの描画の刻み（1秒に60回など）に関係なく、ゲームの状態が「操作の時刻」だけで完全に決まる**必要がある。

- **今の作り**：コンベアの移動距離を、フレームごとに「経過時間×速度」を足して求めている。足す刻みが違うと小数の丸め誤差がわずかに変わる（ふつうは影響しないが、境界ぎりぎりの入力で判定が変わる可能性がゼロではない）。
- **変更後**：出来事（出現・通過・仕分け）が起きた時刻と位置を基準として覚えておき、位置は毎回「基準＋(今の時刻−基準の時刻)×速度」で計算する。これで途中を何回に分けて進めても、計算結果が1ビットも変わらない。
- **時刻を1ミリ秒単位にそろえる**：ゲームに渡す時刻（フレームの時刻・入力の時刻）を1ミリ秒単位に丸める。人には感じ取れない差。これで操作記録を整数（ミリ秒）で正確に送れる。
- 入力の時刻が直前のフレームより前になった場合、ゲームは「今の時刻」で判定している（今までどおり）。記録には**実際に判定に使った時刻**を残す。
- 同時押しで無効になった入力（D-06）や、待機中で無視された入力は状態を変えないので記録しない。
- core で使う計算は四則演算と `Math.max/min/round/floor/imul` だけで、どのブラウザ・サーバーでも同じ結果になる（`sin` など環境で差が出うる関数は使っていない）。

### 16.3 操作記録

- 1回の仕分けにつき「時刻（ミリ秒、前の操作との差）」と「左右」を記録。`差×2＋(右なら1)` を36進数にして `,` でつなぐ文字列にする。
- 例：10分のプレイで約2,000回仕分け → 約8KB。上限は 200KB（約60分ぶん）とし、超えたら登録不可。
- 送信内容：`{ token, name, log, score, ruleVersion }`。`score` はブラウザが計算した点数で、サーバーの再計算と一致しなければ拒否（プログラムの不具合の検出にも使う）。

### 16.4 整理券（種の発行）

- `GET /api/run` は `{ token, seed }` を返す。`token` は「種・発行時刻・ランダムなID・ルールの版」に、サーバーだけが知る秘密の鍵で署名したもの（HMAC-SHA256）。データベースには書かない。
- ブラウザはタイトル画面・リザルト画面・一時停止画面を出したときに、次のゲーム用に1枚先に取っておく（プレイ中は通信しない。16.10。実装時に「ゲームを始めたとき」から一時停止画面に変更）。スタート時に手元にあればその種で遊び、なければ今までどおりブラウザで作った種で遊ぶ（そのプレイは登録不可）。
- `?seed=` 指定（開発用）のプレイは登録不可。
- 整理券の有効期限は24時間。

### 16.5 登録時のサーバーの検査（D-21 レベル2）

上から順に検査し、1つでも外れたら登録しない。

| 順 | 検査 | 外れたときの表示 |
|---|---|---|
| 1 | 送信元が公開URL（または開発用の localhost） | — |
| 2 | 同じ接続元から10分間に10回を超える登録はできない | 「時間をおいてもう一度お試しください」 |
| 3 | 名前のルール（16.6） | 「この名前は使えません」 |
| 4 | 整理券の署名が正しい・24時間以内・ルールの版が今と同じ | 版違い：「ゲームが更新されました。ページを再読み込みしてください」／その他：「登録できませんでした」 |
| 5 | 同じ整理券がすでに使われていない（ランダムIDの重複を禁止） | 「登録済みです」 |
| 6 | 操作記録を再計算し、ゲームが終了（ミス3回）していること、点数が送られた点数と一致すること、点数が1以上 | 「登録できませんでした」 |
| 7 | 整理券の発行からの実際の経過時間 ≧ プレイ時間 − 3秒 | 「登録できませんでした」 |

接続元は、IPアドレスを秘密の値と混ぜて元に戻せない形（ハッシュ）にして、連続投稿の判定用の表にだけ1時間置き、その後消す。ランキングの表には入れない。

### 16.6 名前

- 前後の空白を除き、全角英数字などを半角にそろえる（Unicode NFKC 正規化）。
- 1〜10文字（絵文字や濁点つきの文字も見た目の1文字で数える）。
- 改行・タブ・見えない文字（制御文字・幅のない文字）は不可。
- 禁止語：差別・性的な語などの短い一覧をコードに持ち、ひらがな/カタカナ・大文字/小文字の違いを無視して、名前に含まれていたら不可。完全ではないので D-27（削除）で補う。
- 同じ名前は何件でも登録できる（C-53）。

### 16.7 データベース（D1）

```sql
CREATE TABLE scores (
  id         INTEGER PRIMARY KEY,
  run_id     TEXT    NOT NULL UNIQUE,  -- 整理券のランダムID（使い回し防止）
  name       TEXT    NOT NULL,
  score      INTEGER NOT NULL,
  max_combo  INTEGER NOT NULL,
  play_ms    INTEGER NOT NULL,
  rule_ver   INTEGER NOT NULL,
  created_at INTEGER NOT NULL          -- 登録時刻（ミリ秒）
);
CREATE INDEX scores_rank ON scores (score DESC, created_at ASC);
CREATE TABLE rate (ip_hash TEXT NOT NULL, at INTEGER NOT NULL);
CREATE INDEX rate_ip ON rate (ip_hash, at);
```

- 31位以下の記録も消さずに残す（順位の計算と、削除後の繰り上がりのため）。操作記録は保存しない。
- 順位：`自分より点数が高い件数＋1`。同点は同じ順位、並びは先に登録した方が上（D-26）。

### 16.8 API

| API | 返すもの |
|---|---|
| `GET /api/run` | `{ token, seed, ruleVersion }` |
| `GET /api/ranking` | `{ entries: [{ rank, name, score, at }]（最大30件）, ruleVersion }` |
| `POST /api/scores` | 成功：`{ id, rank, entries }`／失敗：`{ error: 種類 }`（400番台） |

- 公開URLと localhost 以外のページからの呼び出しは受け付けない（CORS）。
- ランキングの取得は10秒間キャッシュしてよい（大勢が同時に開いても読み込み回数を抑える）。

### 16.9 画面

**タイトル**：「遊び方」の下に「ランキング」ボタンを追加。

**ランキング画面（新規）**
- 上に「あなたの自己ベスト ○○点（この端末）」。
- 1位〜30位の表：順位・名前・スコア・登録日（月/日、見ている端末の時刻で表示）。1〜3位は色を変える。直前に自分が登録した記録は強調表示。

**文字入力とキー操作（P-26）**
- 名前欄で文字を入力しているときは、ゲームのキー（A・D・←・→・Enter・R・Space・Esc）をゲームの操作として扱わない（文字入力を優先）。
- 名前欄で Enter（日本語入力の変換確定中を除く）＝［ランキングに登録］。
- 名前欄の文字の大きさは16px以上（iPhone の自動拡大を防ぐ）。名前欄だけは長押し・文字選択を許可する（今は画面全体で禁止している）。
- スマホでキーボードが出て画面の高さが変わっても、リザルト画面は内容をスクロールできるようにする。

### 16.10 通信

- 通信先のURLはビルド時の設定（`VITE_RANKING_API`）。公開用は `.env.production` に書いてリポジトリに入れる（公開して問題ない値）。開発用は `.env.development` で `http://127.0.0.1:8788`（ローカルのサーバー。8787 はこのPCで別のプログラムが使っているため）。
- 1回の通信は5秒で打ち切る。失敗してもゲームの進行・入力・描画には影響させない。**プレイ中は通信しない**（次回用の整理券の取得は、ゲーム終了後に行う）。

### 16.11 ルールの版と、第4段階の調整との関係

- 難易度・得点などの数値（`config.ts`）を変えると、同じ操作でも結果が変わるため、`RULE_VERSION` を1つ上げ、サーバーも同時に更新する。
- 古い版のページを開いたままの人は登録できず「ページを再読み込みしてください」と出る。
- 数値を変えたとき、それまでのランキングを残すか消すかは、**その時にユーザーに確認する**（難しさが変わると点数を比べられなくなるため）。版はデータベースにも記録しておく。

### 16.12 公開と更新

- サーバー：`server/` で `wrangler deploy`（Claude がこのPCから実行）。データベースの作成・秘密の鍵の登録（鍵は Claude が乱数で作る）も同様。

- サーバーの自動公開（GitHub Actions から）は、Cloudflare の鍵をユーザーが GitHub に登録する必要があるため、今回は行わない。

  - 実際（2026-11-10）：サブドメインは聞かれず、初回公開時に自動で `haniwa-dogu-sort` になった。サーバーのURLは https://haniwa-dogu-ranking.haniwa-dogu-sort.workers.dev 。

### 17.4 ゲーム本体（core）の変更

- `new Game(seed, difficulty)`。難易度は `easy | normal | hard | extreme`。
- **乱数の種を難易度で混ぜる**：`実際の種 = mix(種, 難易度の番号)`。同じ整理券でも難易度が違えば出土品の並びがまったく変わる。
  - 理由：混ぜないと、出土品の並び（左右）は難易度に関係なく同じになり、「かんたんで遊んだ操作記録を激むずとして送って4倍の点数を得る」不正ができてしまう。混ぜておけば、別の難易度として再計算すると結果が合わず拒否される。
- 種類の選び方（spawner）：17.2 のとおり、累計出現数から「今出てよい種類」を決め、その中から均等に選ぶ。
- 点数：17.1 の式。
- `RULE_VERSION` を 2 に上げる（ルールが変わるため。設計書 16.11）。

### 17.5 ランキングのサーバーの変更

- データベース：`scores` に `difficulty TEXT NOT NULL DEFAULT 'normal'` を追加（今の記録は自動的に「ふつう」になる。D-35）。
- 登録：送信内容に `difficulty` を追加。サーバーはその難易度で再計算する（17.4 の種の混ぜ方も同じ）。知らない難易度名は拒否。
- ランキングの応答：各記録に `difficulty` を追加。
- 版が上がるので、版1のページから登録しようとした人には「ページを再読み込みしてください」と出る（16.5 の4）。

## 18. 追加：デモムービー（v1.3・2026-11-13 承認済み）

> 状態：**承認済み（2026-11-13、ユーザー「承認して実装へ」。道具のダウンロード約100MB の許可を含む）**。要件：要件定義書 第10章（C-59〜C-64、D-40〜D-45）。

### 18.1 全体の流れ

1. `demo/` の録画スクリプトが、このPCでゲームの開発用サーバー（`vite`）を起動する。
2. 先にゲーム本体の計算（`src/core` の `Game`）を Node の中で動かし、決まった種（seed）・激むずで「いつ・どちらを押すか」の予定表を作る（18.5）。
3. Microsoft Edge（Windows に最初から入っている）を画面なしで開き、**ページの時計を止めて**、1/30秒ずつ手で進めながら1コマずつ撮る（18.4）。予定表の時刻ぴったりにキー・タップを入れる。
4. 撮ったコマをそのまま ffmpeg に流して mp4 にする。切ってつなぐ部分（D-41）は、撮らずに時計だけ進める。
5. 縦と横で 2〜4 を2回行う。

ゲーム本体（`src/`）は変えない。公開するゲームには何も入らない。

### 18.3 ゲームの開き方

- URL：`http://localhost:<空いている番号>/?seed=<決めた種>`。`?debug=1` は使わない（判定の線が画面に出るため）。
- **ランキングのサーバーには一切つながない**：ページからの通信は localhost 以外をすべて止める。ローカルのランキングサーバーも起動しないので、記録はどこにも入らない。
- `?seed` で遊ぶと結果画面に「このプレイはランキングに登録できません」と出るため、録画のときだけ登録欄を隠す（録画スクリプトが CSS を差し込む。ゲーム本体は変えない）。タイトルの「ランキング」ボタンはそのまま映る。
- 音は鳴らさない（録画に入らないため）。

### 18.4 1コマずつ撮る仕組み

- Playwright の時計の機能で、ページの `performance.now()`・`setTimeout`・`requestAnimationFrame` を止め、1/30秒（33.333ms）ずつ進める。進めるたびにゲームが1回描かれ、そこで画面を撮る。
- 時計を先に大きく進めておく（約3時間ぶん）。キーやタップの時刻はゲームの換算（`eventTime`）で「止めた時計の今」に置き換わるので、押した時刻が予定表とずれない。
- 文字の点滅やボタンの光り方など CSS の動きは、時計を止めても勝手に進んでしまう。そこで、コマごとに `document.getAnimations()` で全部を止め、止めた時計に合わせた位置へ動かしてから撮る。
- 画面の大きさ：
  - 縦：スマホとして開く（タッチあり）。幅540×高さ960、表示倍率2 → **1080×1920**。ゲームは「縦持ち」の配置になり、画面下の左右ボタンを押す。
  - 横：PC として開く（タッチなし）。幅960×高さ540、表示倍率2 → **1920×1080**。キーボードの ← → で仕分ける。
  - ゲームの描画は表示倍率2まで細かく描くので、どちらもぼやけない。

### 18.5 自動プレイ（予定表）

- Node でゲーム本体の計算を同じ種・激むずで動かし、押す時刻を決める。
  - ふだんは、出土品が判定の範囲に入ってから少し後（0.05〜0.25秒。種から決まる揺らぎ）に正しい側を押す。人が遊んでいるように見せるため、毎回同じ間合いにはしない。
  - 最後の場面で、わざと反対側を押して3回ミスする（「ちがう！」が3回出てゲームオーバー）。
- 種は、いくつか試して次の条件を満たすものを選ぶ：最初の数個に、はにわと土偶の両方が出る／見せる範囲で「新しい出土品が加わった！」と「10コンボ」が出る／いろいろな種類が映る。
- 撮り終えたら、画面の結果の点数と Node で計算した点数を比べ、違えば失敗として止める（押した時刻のずれに気づくため）。

### 18.7 重ねて表示するもの（D-42・D-43）

すべて録画スクリプトがページの一番上に差し込む（ゲーム本体とは別）。動きは CSS の動きを使わず、コマごとに位置や透明度を計算して決める（止めた時計とずれないようにするため）。

## 19. 追加：難易度カスタム（v1.4・2026-11-14 承認済み）

> 状態：**承認済み（2026-11-14、ユーザー「承認して実装へ」。R19〜R23 を含む）**。要件：要件定義書 第11章（C-65〜C-70、D-46〜D-52）。

### 19.1 方針

- 今の4つの難易度は、**同じ種・同じ操作なら1点も変わらない**ように作る。ゲーム本体（`src/core`）には「カスタムのときだけ通る道」を足すだけにし、今の道の計算は変えない。
- そのため **`RULE_VERSION` は 2 のまま、ランキングのサーバーは更新しない**（再計算の結果が変わらないため）。サーバーは「カスタム」を知らないので、もし送られても `invalid` で断る（作りとしては送らない）。
- これを確かめるため、**変更前のゲームで計算した点数を固定値としてテストに入れ**、変更後も同じになることを毎回確かめる（19.8）。

### 19.2 設定の形（`src/core/config.ts`）

```ts
type PlayMode = Difficulty | 'custom';
interface CustomSettings {
  variants: string[];   // 選んだ出土品の id（全32種から。全体で1つ以上：D-46）
  speed: number;        // ×0.5〜×3.0、0.1刻み（D-49）
  speedUp: boolean;     // 速度アップ（C-69）
}
```

| 項目 | 内容 |
|---|---|
| 初期設定（D-51「初期設定に戻す」） | はにわ・土偶とも一覧の先頭から4種（＝「ふつう」の最初と同じ）、×1.0、速度アップ ON |
| 値の整え方 `normalizeCustom` | 知らない id と重複を捨てる。並びは一覧の順にそろえる。1つもなければ初期設定。速度は 0.5〜3.0 に収め、0.1 単位に丸める |
| 速さの目安 `speedLabel`（D-49） | ×0.5〜0.6「とてもゆっくり」、×0.7〜0.9「ゆっくり」、×1.0「ふつう」、×1.1〜1.4「はやい」、×1.5〜1.9「とてもはやい」、×2.0〜3.0「激はや」 |

### 19.3 ゲーム本体の変更（カスタムのときだけ）

| 場所 | 変更 |
|---|---|
| `Game(seed, mode, cfg, custom?)` | 2つ目を `PlayMode` に広げ、カスタムのときは4つ目に設定を渡す |
| 乱数の種 `mixSeed` | カスタムは番号5で混ぜる（今の4つは今の番号のまま＝結果は変わらない） |
| 速さ | 流れる速さ ＝ 今の計算 × 設定の速度。出てくる間隔は「距離」で決まっているので、速さを上げると時間の間隔も同じ割合で縮む（D-49「一緒に変わる」）。判定の範囲も距離なので、押せる時間も同じ割合で短くなる（P-39） |
| 速度アップ OFF | 速さと間隔の計算に使う「何個目か」を常に0とみなす（最初の速さと間隔のまま続く） |
| 種類 | 選んだものだけから選ぶ。途中で増えない（D-47。「新しい出土品が加わった！」も出ない）。直前と同じ種類を避ける決まりは今と同じ |
| はにわ・土偶の割合（D-48） | 基準の割合 r ＝ 選んだはにわの数 ÷ 選んだ数。今の出方（ランダム・連続・交互・偏り）で決まる確率 p を、r に合わせてずらす：p' ＝ p·r ÷ (p·r ＋ (1−p)(1−r))。r＝50% なら今と同じ、ランダムの区間では p' ＝ r。片方を1つも選んでいないときは、もう片方だけを出す（0%・100%） |
| 点数 | 倍率 ×1.0（D-52） |

### 19.8 テスト

1. **今の4つの難易度が変わらないこと**：変更前のコードで、決まった種と操作の点数・正解数・最大コンボ・ゲームオーバーの時刻を計算し、その値をテストに書き込む。変更後に一致することを確かめる。サーバーの再計算（`replay`）でも同じ。
2. カスタム：選んだ種類しか出ない／途中で増えない／片方だけ選ぶと片方だけ出る／割合が選んだ数に近い（例：はにわ4・土偶12 で、1万個のうちはにわが約25%）／速度×2 で出てくる間隔が半分／速度アップ OFF で間隔と速さが変わらない／点数の倍率が×1.0。
3. 設定の整え方：知らない id・重複・空・範囲外の速度。
4. 画面：ブラウザで、カスタム設定 → 遊ぶ → 結果（登録欄なし・自己ベスト「—」）→ リトライ、スマホの大きさでの見え方、キー操作。
