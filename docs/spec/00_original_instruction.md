# Claudeへの開発指示書
## はにわと土偶のエンドレス仕分けゲーム

あなたはゲーム開発に精通したソフトウェアエンジニアです。

以下の仕様に基づき、PC向けミニゲーム「はにわと土偶の仕分けゲーム」を開発してください。

## 1. ゲーム概要

### ジャンル
- 2択仕分けゲーム
- エンドレス型
- ベルトコンベア方式
- 反射神経・判断力・処理速度を競うゲーム

### 基本コンセプト
ベルトコンベアで次々と流れてくる「はにわ」と「土偶」を、左右のキーで正しく仕分けるゲーム。

操作は非常にシンプルにし、プレイヤーが長時間繰り返し遊びたくなるゲーム性を目指す。

## 2. 基本操作

| キー | 動作 |
|---|---|
| A / ← | はにわを左に仕分け |
| D / → | 土偶を右に仕分け |
| Space | 一時停止・再開 |
| Esc | メニュー |

### 入力ルール
- 1回のキー押下につき1個を処理する。
- キー長押しによる連続仕分けは禁止する。
- 左右同時押しは無効とする。
- 仕分けのアニメーション中でも次の操作を受け付ける。
- 入力対象はコンベア上の最前列の出土品のみとする。

## 3. コンベアシステム

- コンベアは画面上部から下部に向かって動く。
- 出土品は上から順番に生成される。
- コンベアはプレイ中、基本的に停止しない。
- 出土品同士は重ならないようにする。
- 複数個の出土品が同時に画面内に存在できる。
- 先頭から順番に仕分ける。
- 仕分けられた出土品は左右の回収箱へ移動する。

### 重要事項
仕分け成功時にコンベアを停止させたり、後続の出土品を瞬間移動させたりしないこと。

## 4. 判定システム

以下の4つの状態を実装する。

1. 待機エリア
2. 先行入力エリア
3. 通常判定エリア
4. 判定ライン通過

### 先行入力について【確定仕様】

出土品が通常判定エリアに入る少し前から仕分けを許可する。

先行入力エリアでキーを押した場合、その瞬間に仕分けを実行する。

キー入力の予約方式にはしない。

### 各状態での動作
- 待機エリア：入力を無視する。
- 先行入力エリア：即座に正誤判定する。
- 通常判定エリア：即座に正誤判定する。
- 判定ライン通過：未仕分けとしてミス扱いにする。

判定可能時間の初期案は以下とする。

- 先行入力：0.35秒
- 通常判定：1.15秒
- 合計：1.50秒

これらの数値は仮設定とし、調整可能にすること。

## 5. 正解・ミス・ゲームオーバー

### 正解時
- 出土品を正しい回収箱へ移動する。
- 基本得点100点を加算する。
- コンボ数を1増加する。
- 得点とコンボ数を画面に表示する。

### 不正解時
- ミス数を1増やす。
- コンボ数を0にする。
- 不正解演出を表示する。

### 未仕分け時
- 判定ラインを通過した場合はミス扱いとする。
- コンボ数を0にする。

### ゲームオーバー
- ミスが3回に達した時点でゲーム終了。
- 最終得点、仕分け数、最大コンボ、正答率、プレイ時間を表示する。
- リトライ機能を実装する。

## 6. 得点とコンボ倍率

| コンボ数 | 得点倍率 |
|---|---|
| 0〜9 | 1.0倍 |
| 10〜19 | 1.2倍 |
| 20〜39 | 1.5倍 |
| 40〜69 | 2.0倍 |
| 70〜99 | 2.5倍 |
| 100以上 | 3.0倍 |

得点は「100 × コンボ倍率」で計算する。

コンボ倍率の判定タイミングは仕様として明確に定義すること。

## 7. 出土品の生成

### 分類
- はにわ
- 土偶

基本出現確率は、それぞれ50%とする。

### 出現パターン
- 完全ランダム：50%
- 同分類の連続：20%
- 交互出現：15%
- 片方に偏る：15%

これらはパターン選択時の重みであり、個々の出土品の確率ではない。

出現パターンは一定個数ごとに抽選し直す。

同じ分類が何回連続しても、次の分類を確定的に予測できない設計にする。

## 8. 出土品の種類

はにわと土偶には、それぞれ複数の見た目を用意する。

例：

### はにわ
- 人物型
- 馬形
- 動物型
- 武人型
- その他

### 土偶
- 遮光器土偶
- ハート形土偶
- 板状土偶
- その他

考古学的な分類を尊重し、実際には土偶であるものをはにわとして扱うような誤分類は避ける。

種類の違いによって得点を変えない。

出土品のサイズや色により、正解が簡単に判別できてしまう仕組みにはしない。

## 9. 難易度システム

累計出現数に応じて難易度が上昇する。

初期バランス案：

| 累計出現数 | コンベア速度 | 出現間隔 |
|---|---|---|
| 0〜19 | 1.0倍 | 2.0秒 |
| 20〜49 | 1.2倍 | 1.7秒 |
| 50〜99 | 1.5倍 | 1.4秒 |
| 100〜199 | 1.8倍 | 1.1秒 |
| 200〜399 | 2.1倍 | 0.9秒 |
| 400以上 | 要調整 | 要調整 |

※この表は以前の暫定案であり、最終確定した数値ではない。

難易度上昇の最終方式は未確定である。

候補：
- A：コンベア速度を上げ続ける。
- B：出現頻度を上げ続ける。
- C：速度と出現頻度の両方を上げる。

現時点ではBを推奨するが、ユーザーの最終承認はまだ得ていない。

実装前に、この方式を確認すること。

また、出現間隔の短縮によって出土品が重ならないようにすること。

## 10. 画面構成

### メイン画面
- 現在のスコア
- 現在のコンボ
- ミス回数
- コンベア
- 流れてくる出土品
- 判定エリア
- 左右の仕分け先

### ゲームオーバー画面
- 最終スコア
- 最大コンボ
- 正解数
- ミス数
- 正答率
- プレイ時間
- リトライボタン

### その他
- タイトル画面
- 一時停止画面
- 操作説明

## 11. 演出

### 正解時
- 出土品が回収箱へ移動する。
- 得点が表示される。
- コンボが増加する。

### 不正解時
- 間違いを視覚的に知らせる。
- ミス数を更新する。

### 高コンボ時
- コンボ数を目立たせる。
- 一定コンボごとに簡単な演出を追加する。

演出は操作を妨げず、テンポのよさを優先すること。

## 12. 設計・実装上の要件

- PCのブラウザで動作するゲームを第一候補とする。
- 操作に対する反応を重視する。
- 描画とゲームロジックを分離する。
- ゲームの進行はフレームレートに依存させない。
- 出現間隔、速度、判定猶予、スコア倍率を設定値として管理する。
- 出土品の追加が容易なデータ構造にする。
- スコア計算と判定処理をテスト可能な設計にする。
- 長時間プレイしてもパフォーマンスが低下しないようにする。
- 外部サービスを必須とせず、ローカル環境で動作できるようにする。

## 13. 開発の進め方

以下の順序で進めること。

### 第1段階：要件定義
これまでの確定事項と未確定事項を整理する。

仕様に矛盾がないか確認する。

特に以下について検討する。
- 先行入力と通常判定の境界
- 複数出土品が判定可能エリアに存在する場合
- 連続入力と同時押しの判定
- 出現間隔とコンベア速度の整合性
- 難易度の上昇方法
- スコアとコンボ計算
- ゲームオーバー時の処理

### 第2段階：詳細設計
要件定義の承認後、ゲームロジックと画面構成を設計する。

### 第3段階：実装
詳細設計の承認後、実装を開始する。

### 第4段階：動作確認・調整
基本操作とゲーム進行を確認し、ゲームバランスを調整する。

## 14. Claudeへの重要な指示

あなたには、設計上の問題点を発見し、改善案を提示する役割も求めます。

そのため、単に指示を実装するのではなく、ゲームとして面白く成立するかを検討してください。

ただし、以下を厳守してください。

1. 確定した仕様を独断で変更しない。
2. 未確定事項を確定済みとして扱わない。
3. 仕様の矛盾や技術的な問題があれば指摘する。
4. 重要な設計判断は選択肢と推奨案を提示する。
5. ユーザーの承認を得てから次工程へ進む。
6. 各工程の成果物をファイルに保存し、後から参照できるようにする。
7. Claudeの会話セッションが切り替わっても開発を継続できるよう、決定事項・未決定事項・進捗・次の作業をドキュメントに残す。

## 最初に実施すること

まず、上記の内容を読み取り、以下を提示してください。

1. 現時点で確定している仕様
2. まだ決定していない仕様
3. ゲーム設計上の問題点や矛盾
4. 改善が必要と思われる項目
5. 次に決めるべき仕様と推奨案
